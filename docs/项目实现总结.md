# MindPilot 项目实现总结

> 一个「万能视频下载 + 转写 + AI 总结」的轻量网站。后端 FastAPI（无数据库），前端单页（Tailwind 风格），
> 三大能力均以「门面 + 可插拔包」的架构组织，便于按平台 / 服务商横向扩展。
>
> 本文沉淀截至当前版本的完整实现：视频下载、视频转写、AI 总结。需求背景见 [项目需求说明.md](./项目需求说明.md)。

---

## 一、总体架构

```
MindPilot-GPT/
├── backend/                  # FastAPI 后端（三个能力包 + 入口）
│   ├── main.py               # 应用入口：路由 + 静态前端托管
│   ├── downloader/           # 能力一：视频解析下载（门面 + 注册表 + 平台模块）
│   │   ├── __init__.py       #   门面 & 调度器（extract_info / download / ffmpeg_available）
│   │   ├── registry.py       #   平台解析器注册表（SPECIFIC_EXTRACTORS）
│   │   ├── douyin.py         #   抖音专用解析器（去水印）
│   │   ├── generic.py        #   通用解析器（yt-dlp 兜底，覆盖绝大多数平台）
│   │   └── common.py         #   共享工具（临时目录、ffmpeg 定位）
│   ├── transcribe/           # 能力二：转写（字幕优先 → ASR 兜底）
│   │   ├── __init__.py       #   门面 & 两级编排器（transcribe）
│   │   ├── subtitles.py      #   第一级：yt-dlp 抓视频自带字幕（含 Cookie 注入）
│   │   ├── asr.py            #   第二级：多 provider 语音识别链（config-gated）
│   │   └── audio.py          #   ASR 前置：把 URL 变成可上传音频（ffmpeg 转码）
│   └── ai/                   # 能力三：AI 总结（模型无关，多服务商可切换）
│       ├── __init__.py       #   门面（summarize / ai_available / current_label）
│       ├── config.py         #   多服务商预设 + 环境变量解析
│       ├── llm.py            #   OpenAI 兼容 /chat/completions 调用（含采样参数降级重试）
│       └── summary.py        #   提示词工程 + 结构化 JSON 解析规整
├── frontend/                 # 单页前端（index.html + app.js，Tailwind 风格）
├── tests/                    # 离线单测 + 端到端脚本
├── docs/                     # 文档
├── requirements.txt
└── .env.example              # 配置模板（复制为 .env 填写，.env 已被 gitignore）
```

**贯穿全局的设计原则：**

- **门面 + 可插拔**：每个能力包对外只暴露 `__init__.py` 里的少量函数，上层（`main.py` / 前端）
  不感知底层实现；新增平台 / 服务商只在包内加一处，符合开闭原则。
- **配置驱动、优雅降级**：AI 与 ASR 都是「配了 Key 才启用」，未配置时给出可操作的友好提示，
  而非让服务崩溃——下载与字幕提取始终可用。
- **密钥安全**：所有 API Key 只从环境变量 / `.env` 读取，`.env` 已入 `.gitignore`，
  `.env.example` 仅保留占位符，绝不提交真实密钥。

## 二、能力一：视频解析下载

### 调度机制
门面 `downloader` 按 `registry.SPECIFIC_EXTRACTORS` 顺序用各模块的 `can_handle(url)` 匹配专用解析器，
都不命中则回退到 `generic`（基于 yt-dlp 的通用解析器）：

```
extract_info(url) / download(url, format_id)
        └── _pick(url)：遍历注册表 → 命中专用（如 douyin）用之，否则 generic
```

### 平台解析器统一契约
每个平台模块实现三个函数，即可被门面自动调度：

| 函数 | 职责 |
|------|------|
| `can_handle(url) -> bool` | 是否由本平台处理该链接 |
| `extract_info(url) -> dict` | 解析标题 / 封面 / 时长 / 可选清晰度列表 |
| `download(url, format_id) -> dict` | 服务端下载，返回 `{filepath, filename, ...}` |

### 两类解析器
- **generic（yt-dlp 通用）**：站在开源巨人肩膀上，覆盖 YouTube / B站 / 抖音网页版等十余万站点；
  用 `imageio-ffmpeg` 内置的 ffmpeg 合并音视频（高清必需），零配置。
- **douyin（抖音专用）**：抖音分享短链无法用通用逻辑，走专用链路——
  分享链 302 跳转 → iteminfo API 取真实地址 → `playwm` 换 `play` 去水印。

### 新增平台步骤
1. 新建 `backend/downloader/<platform>.py`，实现上述三函数；
2. 在 `registry.py` 的 `SPECIFIC_EXTRACTORS` 里 import 并加入列表（越靠前优先级越高）。

## 三、能力二：视频转写（字幕优先 → ASR 兜底）

转写门面 `transcribe(url)` 编排**两级策略**，返回统一结构 `{title, language, language_name, source, segments, text, char_count, ...}`，
其中 `source ∈ {manual, auto, asr}`：

```
transcribe(url)
  ├── 第一级 subtitles.transcribe(url)   # yt-dlp 抓视频自带人工/自动字幕（免费、快、带时间戳）
  └── 抓不到时（catch TranscribeError）
        ├── 未配 ASR → 抛「分平台可操作提示」（抖音建议配 ASR、B站建议配 Cookie）
        └── 已配 ASR → 第二级：audio.acquire_audio(url) → asr.transcribe_audio(path)
```

### 第一级：字幕提取（subtitles.py）
- 用 yt-dlp 抓 `subtitles`（人工）与 `automatic_captions`（自动），解析 VTT/SRT、去重、按语言择优；
- **Cookie 注入**：B站等平台的语音/AI 字幕需登录态。支持两种配置（二选一）：
  - `COOKIE_FILE`：指向 Netscape 格式 `cookies.txt`；
  - `COOKIES_FROM_BROWSER`：直接从本机浏览器读取（如 `edge`、`chrome:Profile 1`）。

### 第二级：语音识别兜底（asr.py + audio.py）
当视频根本没有字幕可抓（抖音无字幕轨、B站未登录）时启用。

- **audio.py（音频获取）**：路由与下载层一致——抖音走 `douyin.download`，其他走 yt-dlp `bestaudio`；
  统一用 ffmpeg 转 **16kHz 单声道 mp3**（体积小、满足 base64 上限、ASR 通用）。
- **asr.py（多 provider ASR 链，config-gated）**：按环境变量组成「可用 provider 链」，依次尝试直到成功；
  未配任何 Key 时 `asr_available()` 为 False，上层降级为提示而非报错。

| provider | 只需填的 Key | 调用风格 | 默认端点 / 模型 | 备注 |
|----------|-------------|---------|----------------|------|
| 硅基流动 | `SILICONFLOW_API_KEY` | `/audio/transcriptions`（multipart 直传） | `api.siliconflow.cn/v1` · `FunAudioLLM/SenseVoiceSmall` | **免费不限量**、中文强、≤50MB |
| 通义 Qwen | `DASHSCOPE_API_KEY`（或 `QWEN_API_KEY`） | `chat.completions` + `input_audio`（base64） | `dashscope.../compatible-mode/v1` · `qwen3-asr-flash` | base64 后 ≤10MB |
| 自定义 | `ASR_API_KEY` + `ASR_BASE_URL` + `ASR_MODEL`（三者齐全） | 由 `ASR_STYLE` 决定 | 用户自定义 | 接入 Groq / OpenAI / 自建 |

> **要点**：硅基流动与 Qwen 是内置预设，`base_url`/`model` 已写死默认值，**只需填 Key**；
> 仅当要覆盖默认（`SILICONFLOW_BASE_URL`/`SILICONFLOW_ASR_MODEL` 等）或接入自定义端点时才需额外配置。
> 默认尝试顺序为「硅基流动 → DashScope」，可用 `ASR_PROVIDER=a,b` 显式改序；文件超某 provider 上限会自动跳过并在错误里说明。

- ASR 结果无精确时间戳时，按中文标点切分并合并为 ≥20 字的分段，前端 `language_name` 展示「语音识别 · <provider>」，
  `fmtTs(undefined)` 对无时间戳分段自动留空——**前端零改动即可渲染**。

## 四、能力三：AI 总结（多服务商大模型）

门面 `ai.summarize(text, title)` 把字幕文本喂给大模型，产出**结构化中文总结**。

### 多服务商配置（config.py）
一份代码接入多家 OpenAI 兼容端点，靠环境变量切换，新增服务商只在 `PROVIDERS` 加一行：

| provider | 默认端点 | 默认模型 | Key 变量（支持多别名） |
|----------|---------|---------|----------------------|
| deepseek | `api.deepseek.com/v1` | `deepseek-chat` | `DEEPSEEK_API_KEY` |
| zhipu（智谱 GLM） | `open.bigmodel.cn/api/paas/v4` | `glm-4-flash` | `ZHIPU_/GLM_/BIGMODEL_API_KEY` |
| qwen（通义） | `dashscope.../compatible-mode/v1` | `qwen-plus` | `DASHSCOPE_/QWEN_API_KEY` |
| kimi（Moonshot） | `api.moonshot.cn/v1` | `moonshot-v1-8k` | `MOONSHOT_/KIMI_API_KEY` |
| openai | `api.openai.com/v1` | `gpt-4o-mini` | `OPENAI_API_KEY` |

**标识解析（`_resolve_provider`）**：精确 provider > 别名（`glm→zhipu`、`tongyi→qwen`、`moonshot→kimi`、`gpt→openai`）> 前缀
（用户常把「服务商-模型」连写，如 `kimi-k2.6`、`gpt-4o`，前缀命中时把完整值作为 model 覆盖）。
**命名兼容**：推荐 `AI_*`（`AI_PROVIDER`/`AI_API_KEY`/`AI_MODEL`/`AI_BASE_URL`），同时兼容旧的 `LLM_*`（含 `LLM_MODEL_ID`）。

### LLM 调用（llm.py）
httpx 统一调 `/chat/completions`，不绑厂商 SDK。针对**推理类模型**（Kimi-k2、OpenAI o 系列只接受默认 temperature，
传自定义值报 400 `only 1 is allowed`）做了**采样参数降级重试**：命中此类 400 时移除 `temperature`/`max_tokens`，
用服务商默认值重试一次。

### 输出结构（summary.py）
强约束 LLM 输出 JSON，并做稳健解析（容错 ```json 围栏与前后杂文本）与字段规整，前端拿到稳定结构：

```json
{
  "one_line": "一句话概括（≤40字）",
  "summary": "详细摘要（150~300字）",
  "key_points": ["要点1", "要点2"],
  "chapters": [{"title": "章节名", "summary": "该部分讲了什么"}],
  "keywords": ["关键词1"],
  "model": "服务商 · 模型",
  "truncated": false
}
```

- 单次喂给 LLM 的文本上限 `_MAX_CHARS = 30000`，超长自动截断并置 `truncated=true`（前端提示「基于前半部分」）。
- 语义化异常：`AINotConfiguredError`（未配 Key → HTTP 503 引导配置）、`SummarizeError`（调用/解析失败 → HTTP 502）。

## 五、HTTP API

| 方法 & 路径 | 说明 | 主要错误码 |
|-------------|------|-----------|
| `GET /api/health` | 健康检查：`ffmpeg` / `ai`+`ai_provider` / `asr`+`asr_provider` 是否可用 | — |
| `GET /api/info?url=` | 解析视频信息（标题/封面/清晰度） | 400 参数、500 解析失败 |
| `POST /api/download` / `GET /api/download` | 服务端下载并流式回传（GET 便于浏览器原生下载、对手机/大文件友好） | 400 / 500 |
| `POST /api/transcribe` | 转写：字幕优先 → ASR 兜底 | 400 无字幕且无兜底 |
| `POST /api/summarize` | 一站式：转写 → 大模型结构化总结 | 400 转写失败、503 未配 AI、502 总结失败 |

前端为 `frontend/` 下单页应用，由 FastAPI `StaticFiles` 托管在根路径；支持单条 / 批量解析，
每张视频卡片下有「AI 总结」「查看字幕」两个按钮。

## 六、配置（.env）

复制 `.env.example` 为 `.env` 填写（`.env` 已被 gitignore）。三段能力相互独立、均可选：

1. **AI 总结**：`AI_PROVIDER` + `AI_API_KEY`（或各家专属 Key）。不配则仅 `/api/summarize` 返回友好提示。
2. **字幕 Cookie**：`COOKIE_FILE` 或 `COOKIES_FROM_BROWSER`。用于 B站等需登录态才有语音字幕的平台。
3. **ASR 兜底**：`SILICONFLOW_API_KEY`（推荐·免费）或 `DASHSCOPE_API_KEY`；配多个则自动按序尝试。

> 安全红线：真实 Key 只放 `.env`，`.env.example` 永远保持占位符。

## 八、技术栈与依赖

- **后端**：Python 3.11、FastAPI、uvicorn；`yt-dlp`（解析下载）、`imageio-ffmpeg`（内置 ffmpeg）、
  `requests`（抖音专用）、`httpx`（LLM/ASR 调用）、`python-dotenv`（读 `.env`，可选）。
- **前端**：原生 HTML/JS 单页 + Tailwind 风格样式，无构建步骤。
- **无数据库**：后端保持轻量，临时文件用完即清。

## 九、后续可扩展方向

- 下载层：按 `registry` 约定新增更多平台专用解析器（如 TikTok、快手）。
- 转写：接入更多 ASR 服务商（在 `asr.py` 的 `_PROVIDERS` 加一行）；ASR 分段可按英文句号优化。
- AI：在 `ai/` 门面下扩展翻译 / 问答 / 思维导图等能力，复用同一套多服务商配置。
- 产品：付费能力（前端已预留 Pro/Team 升级占位弹窗）。
