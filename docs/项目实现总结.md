# MindPilot 项目实现总结

> 一个「万能视频下载 + 转写 + AI 总结 / 导图 / 问答 + 高赞评论 + 历史 / 合集 / 笔记 / 分享」的一站式内容智能工具。
> 后端 FastAPI（10 个能力包），前端原生 ESM 单页（零构建），各能力均以「门面 + 可插拔」架构组织。
>
> 本文沉淀**当前版本（2026-10-18 代码基线）的完整实现**。文档导航见 [README.md](./README.md)；
> 需求背景与架构原则见 [项目需求说明.md](./项目需求说明.md)；问题清单与演进路线见
> [项目全景分析与技术评审报告.md](./项目全景分析与技术评审报告.md)。

## 一、总体架构

```
MindPilot-GPT/
├── backend/                  # FastAPI 后端（10 个能力包 + 入口）
│   ├── main.py               # 应用入口：业务端点 + 三态门禁 + /api/stream + 管理端点 + 静态托管
│   ├── downloader/           # 能力一：视频解析下载（registry：微信视频号拦截/抖音/快手 → generic 兜底）
│   ├── transcribe/           # 能力二：转写（字幕优先 → Fun-ASR/硅基/Qwen3-ASR 链兜底）
│   ├── ai/                   # 能力三：AI 总结/导图/问答（4 服务商可切换 + JSON 修复 + 模型目录 DB）
│   ├── comments/             # 能力四：高赞评论（bilibili/douyin/kuaishou/ximalaya → generic，无 LLM）
│   ├── auth/                 # 能力五：注册/登录/会话/资料/头像/默认模型（双通道标识符）
│   ├── library/              # 能力六：用户私有资源（历史/合集/QA 会话，/api/me/*）
│   ├── notes/                # 能力七：随手笔记（正文/图片/抽帧，自动保存 + 冲突保护）
│   ├── share/                # 能力八：分享（短链 + SSR 落地页 + 海报数据 + QR + 限流）
│   ├── seo/                  # 能力九：SEO/GEO 基础设施（robots/llms/sitemap/品牌 404）
│   └── storage/              # 底座：db/models(15 表)/keys/repo/singleflight/migrations
├── frontend/                 # 单页前端（index.html + js/ 14 个 ESM 模块，Tailwind 风格）
├── tests/                    # 22 个离线测试文件
├── docs/                     # 文档（入口见 docs/README.md）
├── requirements.txt
└── .env.example              # 配置模板（复制为 .env 填写，.env 已被 gitignore）
```

**贯穿全局的设计原则：**

- **门面 + 可插拔**：每个能力包对外只暴露 `__init__.py` 的少量函数，上层不感知底层实现；
  downloader / transcribe / ai / comments 四包同构——新增平台/服务商只改注册表一行，不改门面与前端。
- **配置驱动、优雅降级**：AI 与 ASR 都是「配了 Key 才启用」，未配置时返回可操作友好提示（503 引导），
  而非服务崩溃——下载与字幕提取始终可用。
- **昂贵结果缓存复用**：转写（抓取/ASR）与总结/导图（LLM）耗时且花钱，结果按内容规范化后全局落库复用，
  同一视频二次访问「秒开」且零成本，并发请求经 single-flight 去重。
- **密钥安全**：所有 API Key 只从环境变量 / `.env` 读取，代码零硬编码。
- **前端零构建零依赖**：原生 ES Modules + Tailwind CDN，导图/海报/图标全部 Canvas/SVG 自绘。

## 二、能力一：视频解析下载（downloader/）

### 调度机制
门面按 `registry.SPECIFIC_EXTRACTORS` 顺序调用各模块 `can_handle(url)`，命中即用专用解析器，都不命中回退
`generic`（yt-dlp 通用解析器，覆盖 YouTube/B 站等千余站点）：

```
extract_info(url) / download(url, format_id) / pick_progressive_format(url)
        └── _pick(url)：遍历注册表 → 命中专用解析器用之，否则 generic
```

### 平台解析器（registry.SPECIFIC_EXTRACTORS）

| 模块 | 定位 |
|------|------|
| `wechat_channels` | **拦截器而非解析器**：微信视频号无公开抓取路径，在白屏阶段即返回中文指引，避免 yt-dlp 白跑完整超时链后抛生英文错误 |
| `douyin` | 抖音专用：分享链 302 取 video_id → iteminfo API → `playwm` 换 `play` 去水印 → 失效回退 `_ROUTER_DATA` |
| `kuaishou` | 快手专用链路 |
| `generic` | yt-dlp 兜底；`imageio-ffmpeg` 内置 ffmpeg 合并音视频（高清必需），零配置 |

统一契约（新增平台只需实现三函数 + 注册表加一行）：`can_handle(url) -> bool`、`extract_info(url) -> dict`、
`download(url, format_id) -> dict`。`pick_progressive_format` 供 `/api/stream` 选单文件渐进式格式（mp4/webm、≤720p）。

### 在线流式播放（main.py /api/stream）
面向抖音等无外链嵌入播放器的平台：服务端把视频完整拉取到磁盘缓存目录（`_STREAM_DIR`，LRU 限量 12 个），
按 HTTP Range 分块回传（支持 `<video>` 拖动 seek），同 URL 并发经 single-flight 只下载一次。
该磁盘缓存同时被笔记抽帧复用（只查不下载，见 §七）。

## 三、能力二：视频转写（transcribe/）

转写门面 `transcribe(url)` 编排**两级策略**，返回统一结构 `{title, language, language_name, source, segments, text, char_count, chapters}`：

```
transcribe(url)
  ├── 第一级 subtitles.transcribe(url)   # yt-dlp 抓视频自带人工/自动字幕（免费、快、带时间戳）
  └── 抓不到时（catch TranscribeError）
        ├── 未配 ASR → 抛「分平台可操作提示」（抖音建议配 ASR、B站建议配 Cookie）
        └── 已配 ASR → 第二级：audio.acquire_audio(url) → asr.transcribe_audio(path)
```

### 第一级：字幕提取（subtitles.py）
- yt-dlp 抓 `subtitles`（人工）与 `automatic_captions`（自动），解析 VTT/SRT、去重、按语言择优；
- **Cookie 注入**（B 站等需登录态）：`COOKIE_FILE`（Netscape cookies.txt）或 `COOKIES_FROM_BROWSER`（如 `chrome`）。
- `chapters`：平台章节（带时间戳），供导图注入「章节时间线」分支与前端跳播。

### 第二级：语音识别兜底（audio.py + asr.py）
无字幕轨时启用。audio.py 与下载层同路由（抖音走专用、其他走 yt-dlp bestaudio），
ffmpeg 转 16kHz 单声道 mp3。asr.py 按 env 组成「可用 provider 链」依次尝试：

| provider | Key | 调用风格 | 特点 |
|----------|-----|---------|------|
| 通义 Fun-ASR-Flash（主） | `DASHSCOPE_API_KEY` | 百炼原生 HTTP + SSE | **唯一带句级时间戳**（可点击跳播），长音频自动切片，按时长计费 |
| 硅基流动 SenseVoiceSmall | `SILICONFLOW_API_KEY` | OpenAI `/audio/transcriptions`（multipart） | 免费不限量、中文强、≤50MB，**无时间戳** |
| 通义 Qwen3-ASR-Flash | `DASHSCOPE_API_KEY` | `chat.completions` + `input_audio`（base64） | 无时间戳 |
| 自定义 | `ASR_API_KEY`+`ASR_BASE_URL`+`ASR_MODEL` | 按 `ASR_STYLE` | 接入 Groq / OpenAI / 自建 |

默认顺序 Fun-ASR → 硅基 → Qwen3-ASR（`ASR_PROVIDER` 可改序）；文件超上限自动跳过；
无时间戳结果按中文标点切分合并为 ≥20 字分段，前端 `fmtTs(undefined)` 留空——前端零改动渲染。

## 四、能力三：AI 总结 / 思维导图 / 问答（ai/）

`ai` 门面在同一套多服务商配置（config.py）与调用层（llm.py）之上提供三种「字幕 → 大模型」能力：

| 能力 | 门面函数 | 产物 | 落库缓存 |
|------|---------|------|---------|
| 总结 | `ai.summarize(text, title)` | 结构化总结（摘要/要点/章节/关键词） | 是 · 跨 URL 复用 |
| 思维导图 | `ai.build_mindmap(text, title)` | 层级树（中心主题 + 多级分支） | 是 · 跨 URL 复用 |
| 问答 | `ai.ask(text, title, question, history=)` | 基于字幕的多轮回答 | 否 · 会话落库（见 §六） |

### 多服务商配置（config.py）
一份代码接入多家 OpenAI 兼容端点，新增服务商只在 `PROVIDERS` 加一行：

| provider | 默认端点 | 默认模型 | Key 变量（多别名） |
|----------|---------|---------|------------------|
| deepseek | `api.deepseek.com/v1` | `deepseek-v4-pro` | `DEEPSEEK_API_KEY` |
| zhipu | `open.bigmodel.cn/api/paas/v4` | `glm-5.3-flash` | `GLM_/ZHIPU_/BIGMODEL_API_KEY` |
| qwen | `dashscope.../compatible-mode/v1` | `qwen3.8-flash` | `QWEN_API_KEY`（代理对）/ `DASHSCOPE_API_KEY`（官方对，与 base_url 同序配对） |
| kimi | `api.moonshot.cn/v1` | `kimi-k2.6` | `KIMI_/MOONSHOT_API_KEY` |
| openai | 预设默认停用 | — | 取消注释即启用 |

- **每服务商专属覆盖**：`*_BASE_URL` / `*_MODEL_ID` / `*_API_KEY` 真正被读取（代理/中转场景按需配）；
- **两阶段 .env 加载**：AI/服务商变量 `.env` 优先于系统环境变量（避免陈旧系统 Key 遮蔽 .env），其余变量系统优先；
- 推荐 `AI_*` 命名（`AI_PROVIDER`/`AI_API_KEY`/`AI_MODEL`/`AI_BASE_URL`），兼容旧 `LLM_*`。

### LLM 调用（llm.py）与 JSON 修复（jsonx.py）
- httpx 统一调 `/chat/completions`，不绑厂商 SDK；推理类模型拒绝采样参数的 400 自动降级重试（移除 temperature 等）；
- **jsonx.py 三级容错**（修复「模型偶发输出非法 JSON」的线上事故，见 bug排查记录）：
  多候选提取（围栏/全文/字符串感知平衡片段/首尾花括号）→ 本地轻修复（补漏逗号、去尾随逗号）→
  **模型修复重试**（把坏输出回传要求只输出修复后 JSON）。

### AI 模型目录（catalog.py + ai_models 表，阶段3 DB 化）
「选择模型」货架已落库：`MODEL_CATALOG` 降级为**出厂种子**，首次启动导入 `ai_models` 表（幂等只补缺）；
运营经管理端点（`ADMIN_API_TOKEN` 门禁）在线上下架/改展示名/调计费倍率，无需发版。
用户选择存 `users.ai_provider/ai_model`，经 `auth.ai_override_cfg` 在 summarize/mindmap/qa 三端点注入；
用户所选服务商未配 Key 时运行期回退全局配置。下架模型即时生效（已选用户自动回退默认）。

### 总结（summary.py）
强约束 JSON + jsonx 容错 + 字段规整，输出 `{one_line, summary, key_points, chapters, keywords, model, truncated}`；
单次文本上限 `_MAX_CHARS=30000` 超长截断并置 `truncated=true`。语义化异常：`AINotConfiguredError`→503、
`SummarizeError`→502。

### 思维导图（mindmap.py）
与总结同构（缓存键含文本+模型+`PROMPT_VERSION`）：限深 `_MAX_DEPTH=4`、限宽 `_MAX_CHILDREN=8`、
兼容 `name/text/label` 等别名字段；`attach_chapters` 把平台章节注入为「章节时间线」分支（节点带时间戳可跳播）；
`to_xmind_bytes` 支持导出 **XMind Zen 文件**（`/api/mindmap/xmind`），补足「导图不可编辑」短板。

### 问答（qa.py）
有状态多轮：`[系统提示(含字幕) + 历史 + 当前问题]`，强约束只依据字幕作答、超范围明说「视频中没有提到」；
`_sanitize_history` 清洗前端传入（单条 ≤2000 字、最近 8 条）。登录态会话编排在 library（见 §六）。

## 五、能力四：高赞评论（comments/，全程无 LLM）

评论是平台结构化数据：抓取走 yt-dlp 或平台 web 接口，「按赞排序取 TopN」是确定性计算——不调 LLM。
门面 `fetch_comments(url, refresh, limit)`：缓存优先（TTL `COMMENTS_CACHE_HOURS` 默认 12h）+ single-flight
+ 锁内双重检查；返回 `{title, source, total, comments, cached}`。

| 平台插件 | 说明 |
|---------|------|
| bilibili | 专用 API：**先领 buvid3/4 指纹再请求**（无指纹裸请求被风控 `-352` 拦截，且旧代码把风控失败误报成「无评论」——见 bug排查记录）；`code` 字段显式校验 |
| douyin | iesdouyin `aweme_id` best-effort，遇风控降级为友好提示 |
| kuaishou | 快手专用 |
| ximalaya | 喜马拉雅专用 |
| generic | yt-dlp getcomments 兜底 |

空评论统一 `CommentsNotSupportedError`→400；网络/解析失败 `CommentsError`→502。

## 六、能力五：认证与个人资料（auth/）

`/api/auth/*`：注册/登录/登出/me/改密/换绑/头像/默认模型。要点：

- **双通道标识符**：邮箱或手机号（E.164 规范化，未接短信服务商，仅格式校验）；两列均 `nullable+unique`
  （NULL 不参与唯一比较，多「仅手机号」用户不冲突）。
- **安全细节**：登录失败对「用户不存在/密码错」同一响应 + 假校验拉平时延（防枚举）；连续失败锁定 + 登录 IP
  滑动窗口限流；改密/换绑需当前密码且失败计入锁定计数；argon2id 优先（未装回退 PBKDF2）+ `needs_rehash`
  透明升级；会话令牌 sha256 落库（库泄露不可反推），改密踢其他设备留当前；头像按**魔数**判型（拒 SVG）、
  分块读取防大文件；个人网站仅 http/https。
- **默认模型**：`PATCH /api/me/ai-settings`（provider/model 同设同清），列白名单校验。
- **三态门禁**（`require_user_if_enabled`）：`AUTH_ENABLED=false` 完全放行（默认，行为与无鉴权时代一致）；
  `true + ALLOW_ANONYMOUS=true` 匿名放行；`true + false` 业务端点一律 401。`/api/health` 与 `/api/auth/*`
  始终开放；**私有资源端点（/api/me/*）永远要求登录，不看灰度开关**。

## 七、能力六：用户私有资源（library/）+ 能力七：随手笔记（notes/）

### library/：历史 / 合集 / QA 会话（/api/me/*）
- **历史**：每（用户, 视频）一行，`kinds` JSON 聚合已生成内容；`content_key` 只引用全局缓存不复制
  （title/url 快照冗余，缓存过期仍可读）；五个内容端点成功后 `BackgroundTask` 异步记录（不拖主响应、容忍丢）。
  上限 `HISTORY_MAX_ENTRIES`（500）滚动淘汰最旧；删除级联本人该视频 QA 会话，不动全局缓存与合集条目。
- **合集**：CRUD + 条目快照与历史解耦；上限合集 50 / 单集条目 200。
- **QA 会话**：`qa_sessions`/`qa_messages` append-only；`/api/qa` 带 `session_id` 时上下文由服务端从 DB 组装
  （`library.ask_in_session`），响应附 `session_id` 供续聊；匿名行为与旧版一致（history 由前端回传）。
- **隔离落在签名层**：store 函数 `user_id` 必填首参（漏传即 TypeError），跨用户访问统一 404（防 IDOR 探测）。
- 侧边栏聚合 `GET /api/me/sidebar` 一次返回合集列表 + 最近历史，免瀑布请求。

### notes/：随手笔记（/api/me/notes/*）
- `user_notes`（Markdown 源文唯一事实源，≤20000 字）+ `note_images`（独立落盘，魔数校验，孤儿清扫）；
- **自动保存**：前端 800ms 防抖 + PATCH 带 `base_updated_at` 乐观并发基线，落后则 409 返回服务端版本
  （内联二选一：加载服务端 / 以我的版本覆盖）；
- **时间戳桥接**：body 内 `@[mm:ss](t=192)` 内联链接存储，服务端解析生成 `marks` 索引（不信任客户端）；
- **三平台截图**：native 播放器前端 canvas 抓帧；B 站/YouTube 后端 `POST /frames` 抽帧
  （复用 `/api/stream` 磁盘缓存只查不下载，无 ffmpeg 回退封面 `frame_type:"poster"`）；**SSRF 防护**
  （字面 IP 全类别拒绝，域名解析结果按显式内网网段清单判定，刻意放过 fake-ip 段保代理用户可用性）；
- 创建/删除笔记与历史 kinds 联动（`note` 徽标零改动生效）。

## 八、能力八：分享（share/）

「分享物即内容样品」：创建分享时快照落库（`shares` 表，不触发 LLM/抓取），接收者**匿名**可读，登录才解锁完整分析。

- **短链**：`code` base62×10（secrets 生成防枚举），`/s/{code}` 服务端渲染落地页（og meta + `<title>`=视频标题 +
  正文首图=封面代理 + noscript 快照 + CTA 深链 `/#/v?url=&tab=`）；撤销 → 410。
- **公开端点**：`/api/share/{code}` JSON 快照（PII 白名单，绝不输出 user_id/原始 url）、`/thumb` 封面同源代理
  （**无 url 入参，SSRF 面为零**，防 canvas 跨域污染）、`/qr` QR SVG（数据域锁定 `PUBLIC_BASE_URL` 前缀）。
- **bundle 载体**：7 种 kind（video/summary/transcript/mindmap/comments/qa/notes）多选聚合为一条链接，
  幂等键 (user, content_key, kind, ref_id)；同码复用更新内容不换链接。
- **安全**：公开端点进程内滑动窗口限流 + view 10 分钟 IP 去重；落地页全量 `escapeHtml` 防 XSS；
  `PUBLIC_BASE_URL` 是短链/QR 域名事实源（反代部署必配）。
- 前端海报在 canvas 绘制（750×1200，CJK 字体零配置），封面走同源代理防污染。
- 详细设计/实现记录见 [分享功能设计方案.md](./分享功能设计方案.md)（v1.1~v1.3，含 21 条实现偏差）。

## 九、能力九：SEO / GEO 基础设施（seo/）

| 端点 | 说明 |
|------|------|
| `/robots.txt` | 屏蔽 `/api/`，放行静态资源与 `/s/`；**AI 搜索/引用类爬虫永远显式放行**（GEO 命根子），训练类爬虫按 `GEO_ALLOW_TRAIN_BOTS` 开关 |
| `/llms.txt` | llmstxt.org 约定的纯 Markdown 站点自述，给 AI 引擎阅读（GEO 落地） |

| `/`、`/index.html` | 动态渲染 SPA 壳：把 `__SEO_BASE_URL__` 占位符替换为站点绝对地址（canonical/og:url/JSON-LD 需要绝对 URL） |
| 品牌化 404 | 非 `/api` 路径 + Accept 含 text/html 的 404 返回品牌页（软 404 信号治理），其余保持默认 JSON 语义 |

## 十、底座：存储与缓存（storage/）

| 模块 | 职责 |
|------|------|
| `db.py` | 按 `DATABASE_URL` 建 engine（默认 `data/mindpilot.db`，WAL；PG 自动配连接池），幂等 `init_db()` |
| `models.py` | 15 张表（见下），`JSONCol = JSON().with_variant(JSONB,"postgresql")` 方言抽象 |
| `keys.py` | `normalize_url`（丢跟踪参数/小写 host/排序 query）+ `transcript_key` / `comments_key` / `summary_key` / `mindmap_key` |
| `repo.py` | 读写缓存 + TTL 判定 + `CACHE_ENABLED` 短路 |
| `singleflight.py` | 进程内按 key 并发去重（转写/总结/导图/评论/流播各一通道） |
| `migrations.py` | **声明式迁移**：启动时备份 → ADD COLUMN → 约束重建表 → 数据修正 → 索引同步，全程幂等 |

### 15 张表：双层模型

**第一层：全局共享内容缓存（5 表，与用户解耦）**

| 表 | 业务键 | TTL |
|----|--------|-----|
| `video_infos` | `transcript_key(url)` | 24h（`INFO_CACHE_HOURS`） |
| `transcripts` | `transcript_key(url)` | 30d（`TRANSCRIPT_CACHE_DAYS`） |
| `ai_artifacts` | `(kind, sha256(文本+模型+PROMPT_VERSION))` | 无（键含版本自然失效）；**原 summaries/mindmaps 两表已合并** |
| `comments` | `comments_key(url)` | 12h（`COMMENTS_CACHE_HOURS`） |
| `ai_models` | `(provider, model)` | 模型目录（管理端维护，出厂种子导入） |

**第二层：用户私有资源（10 表，user_id 列级隔离）**

`users`（双标识符+锁定+ai_provider/ai_model）· `sessions`（令牌哈希）· `user_history` · `qa_sessions` ·
`qa_messages` · `collections` · `collection_items` · `user_notes` · `note_images` · `shares`（公开快照，user_id 仅所有者管理用）。

### 缓存键：命中率的关键
- **转写**：`sha256(normalize_url(url))`——同一视频不同分享链归一到同一键；
- **总结/导图**：`sha256(文本 + 模型 + PROMPT_VERSION)`（导图加域前缀）——跨 URL 复用，改提示词 bump 版本自然失效；
  切换模型 → model 变化 → 自动产生新缓存条目，零迁移；
- **问答**：不缓存（交互式多轮），字幕已在转写层缓存。

### 读写策略
- 查缓存 → 未命中 single-flight 计算 → 锁内双重检查 → 落库；`refresh=True` 强制重算覆盖；
- 转写/总结/导图支持 `refresh_transcribe` 与 `refresh` 分离（Tab 内「重新生成」只重算本层，不级联重做 ASR）；
- `CACHE_ENABLED=false` 读写短路（对照排障）。

## 十二、前端架构

原生 ESM 单页（`<script type="module">`），hash 路由多视图，无构建工具、无第三方运行时依赖：

```
index.html（应用壳：侧边栏 + <main id="view-root"> + modal 容器 + TDK/OG 占位）
js/main.js        bootstrap：health → 登录态 → 侧边栏 → 首路由（唯一同时 import router 与视图处）
js/core.js        工具/请求/缓存 Map/dedup/bus 事件/401 处理（qaCache、notesCache 等按用户私有，auth:changed 时清空）
js/router.js      hash 路由注册表：#/ #/v?url= #/history #/search?q= #/collections #/c/:id
js/sidebar.js     侧边栏（搜索联想/合集/历史/折叠/登录引导卡）
js/auth-ui.js     登录框 + 个人中心 + 默认模型入口
js/model-picker.js「选择模型」弹窗（搜索/分组/当前标记/跟随平台默认）
js/coll-picker.js 「加入合集」popover
js/share.js       分享弹窗（海报 canvas 750×1200 + 多渠道三类动作[intent 直跳/海报+文案/系统分享] + bundle 多选）
js/player.js      三形态播放器：mountNative(/api/stream) / B站 iframe / YouTube iframe
js/views/parse.js      解析首页（单条/批量）
js/views/result.js     结果页：六 Tab（总结/字幕/导图/评论/问答/笔记）+ 播放器 + 加入合集 + 分享（1449 行，见问题清单 G5）
js/views/history.js    历史全部 + 搜索结果
js/views/collections.js 合集管理 + 详情
js/views/notes.js      笔记编辑器（Markdown 双模式 + 时间戳双向桥 + 自动保存状态机）
```

关键机制：模块级缓存 Map + 客户端 `dedup`（同 key 并发复用 Promise）与服务端 single-flight 呼应；
401 由 auth-ui 经 `setUnauthorizedHandler` 注入 core（无反向依赖）；`bus.on('auth:changed')` 清空私有缓存并重渲染当前视图。
