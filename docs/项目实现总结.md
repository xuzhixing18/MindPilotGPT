# MindPilot 项目实现总结

> 一个「万能视频下载 + 转写 + AI 总结」的轻量网站。后端 FastAPI，前端单页（Tailwind 风格），
> 各能力均以「门面 + 可插拔包」的架构组织，便于按平台 / 服务商横向扩展。
>
> 本文沉淀截至当前版本的完整实现：视频下载、视频转写、AI 总结 / 思维导图 / 问答，以及支撑「二次秒开」
> 体验的内容缓存与存储层（阶段0：SQLite + ORM）。需求背景见 [项目需求说明.md](./项目需求说明.md)。

---

## 一、总体架构

```
MindPilot-GPT/
├── backend/                  # FastAPI 后端（三个能力包 + 入口）
│   ├── main.py               # 应用入口：路由 + 静态前端托管
│   ├── downloader/           # 能力一：视频解析下载（门面 + 注册表 + 平台模块）
│   │   ├── __init__.py       #   门面 & 调度器（extract_info / download / ffmpeg_available）
│   │   ├── registry.py       #   平台解析器注册表（SPECIFIC_EXTRACTORS）
│   │   ├── douyin.py         #   抖音专用解析器（去水印）
│   │   ├── generic.py        #   通用解析器（yt-dlp 兜底，覆盖绝大多数平台）
│   │   └── common.py         #   共享工具（临时目录、ffmpeg 定位）
│   ├── transcribe/           # 能力二：转写（字幕优先 → ASR 兜底）
│   │   ├── __init__.py       #   门面 & 两级编排器（transcribe）
│   │   ├── subtitles.py      #   第一级：yt-dlp 抓视频自带字幕（含 Cookie 注入）
│   │   ├── asr.py            #   第二级：多 provider 语音识别链（config-gated）
│   │   └── audio.py          #   ASR 前置：把 URL 变成可上传音频（ffmpeg 转码）
│   ├── ai/                   # 能力三：AI 总结 / 思维导图 / 问答（模型无关，多服务商可切换）
│       ├── __init__.py       #   门面（summarize / build_mindmap / ask / ai_available）
│       ├── config.py         #   多服务商预设 + 环境变量解析（三能力共用）
│       ├── llm.py            #   OpenAI 兼容 /chat/completions 调用（含采样参数降级重试）
│       ├── summary.py        #   总结：提示词工程 + 结构化 JSON 解析规整
│       ├── mindmap.py        #   思维导图：提示词 + 树规整（限深/限宽）+ 缓存 + single-flight
│       └── qa.py             #   问答：基于字幕的多轮 grounded 问答（不落库缓存）
│   └── storage/              # 能力底座：内容缓存与持久化（阶段0 SQLite + ORM）
│       ├── __init__.py       #   门面（init_db / repo / 缓存键 / single-flight 单例）
│       ├── db.py             #   engine / Session / Base / init_db（由 DATABASE_URL 驱动）
│       ├── models.py         #   transcripts / summaries / mindmaps 三张表（通用 JSON 类型）
│       ├── keys.py           #   URL 规范化 + 缓存键（transcript_key / summary_key / mindmap_key）
│       ├── repo.py           #   读写缓存 + TTL 过期 + CACHE_ENABLED 短路
│       └── singleflight.py   #   进程内并发去重（相同 key 只计算一次）
├── frontend/                 # 单页前端（index.html + app.js，Tailwind 风格）
├── tests/                    # 离线单测 + 端到端脚本
├── docs/                     # 文档
├── requirements.txt
└── .env.example              # 配置模板（复制为 .env 填写，.env 已被 gitignore）
```

**贯穿全局的设计原则：**

- **门面 + 可插拔**：每个能力包对外只暴露 `__init__.py` 里的少量函数，上层（`main.py` / 前端）
  不感知底层实现；新增平台 / 服务商只在包内加一处，符合开闭原则。
- **配置驱动、优雅降级**：AI 与 ASR 都是「配了 Key 才启用」，未配置时给出可操作的友好提示，
  而非让服务崩溃——下载与字幕提取始终可用。
- **昂贵结果缓存复用**：转写（抓取/ASR）与总结/思维导图（LLM）耗时且花钱，其结果按内容规范化后全局落库复用，
  同一视频二次访问「秒开」且零成本，并发请求自动去重（详见第五节）。
- **密钥安全**：所有 API Key 只从环境变量 / `.env` 读取，`.env` 已入 `.gitignore`，
  `.env.example` 仅保留占位符，绝不提交真实密钥。

## 二、能力一：视频解析下载

### 调度机制
门面 `downloader` 按 `registry.SPECIFIC_EXTRACTORS` 顺序用各模块的 `can_handle(url)` 匹配专用解析器，
都不命中则回退到 `generic`（基于 yt-dlp 的通用解析器）：

```
extract_info(url) / download(url, format_id)
        └── _pick(url)：遍历注册表 → 命中专用（如 douyin）用之，否则 generic
```

### 平台解析器统一契约
每个平台模块实现三个函数，即可被门面自动调度：

| 函数 | 职责 |
|------|------|
| `can_handle(url) -> bool` | 是否由本平台处理该链接 |
| `extract_info(url) -> dict` | 解析标题 / 封面 / 时长 / 可选清晰度列表 |
| `download(url, format_id) -> dict` | 服务端下载，返回 `{filepath, filename, ...}` |

### 两类解析器
- **generic（yt-dlp 通用）**：站在开源巨人肩膀上，覆盖 YouTube / B站 / 抖音网页版等十余万站点；
  用 `imageio-ffmpeg` 内置的 ffmpeg 合并音视频（高清必需），零配置。
- **douyin（抖音专用）**：抖音分享短链无法用通用逻辑，走专用链路——
  分享链 302 跳转 → iteminfo API 取真实地址 → `playwm` 换 `play` 去水印。

### 新增平台步骤
1. 新建 `backend/downloader/<platform>.py`，实现上述三函数；
2. 在 `registry.py` 的 `SPECIFIC_EXTRACTORS` 里 import 并加入列表（越靠前优先级越高）。

## 三、能力二：视频转写（字幕优先 → ASR 兜底）

转写门面 `transcribe(url)` 编排**两级策略**，返回统一结构 `{title, language, language_name, source, segments, text, char_count, ...}`，
其中 `source ∈ {manual, auto, asr}`：

```
transcribe(url)
  ├── 第一级 subtitles.transcribe(url)   # yt-dlp 抓视频自带人工/自动字幕（免费、快、带时间戳）
  └── 抓不到时（catch TranscribeError）
        ├── 未配 ASR → 抛「分平台可操作提示」（抖音建议配 ASR、B站建议配 Cookie）
        └── 已配 ASR → 第二级：audio.acquire_audio(url) → asr.transcribe_audio(path)
```

### 第一级：字幕提取（subtitles.py）
- 用 yt-dlp 抓 `subtitles`（人工）与 `automatic_captions`（自动），解析 VTT/SRT、去重、按语言择优；
- **Cookie 注入**：B站等平台的语音/AI 字幕需登录态。支持两种配置（二选一）：
  - `COOKIE_FILE`：指向 Netscape 格式 `cookies.txt`；
  - `COOKIES_FROM_BROWSER`：直接从本机浏览器读取（如 `edge`、`chrome:Profile 1`）。

### 第二级：语音识别兜底（asr.py + audio.py）
当视频根本没有字幕可抓（抖音无字幕轨、B站未登录）时启用。

- **audio.py（音频获取）**：路由与下载层一致——抖音走 `douyin.download`，其他走 yt-dlp `bestaudio`；
  统一用 ffmpeg 转 **16kHz 单声道 mp3**（体积小、满足 base64 上限、ASR 通用）。
- **asr.py（多 provider ASR 链，config-gated）**：按环境变量组成「可用 provider 链」，依次尝试直到成功；
  未配任何 Key 时 `asr_available()` 为 False，上层降级为提示而非报错。

| provider | 只需填的 Key | 调用风格 | 默认端点 / 模型 | 备注 |
|----------|-------------|---------|----------------|------|
| 硅基流动 | `SILICONFLOW_API_KEY` | `/audio/transcriptions`（multipart 直传） | `api.siliconflow.cn/v1` · `FunAudioLLM/SenseVoiceSmall` | **免费不限量**、中文强、≤50MB |
| 通义 Qwen | `DASHSCOPE_API_KEY`（或 `QWEN_API_KEY`） | `chat.completions` + `input_audio`（base64） | `dashscope.../compatible-mode/v1` · `qwen3-asr-flash` | base64 后 ≤10MB |
| 自定义 | `ASR_API_KEY` + `ASR_BASE_URL` + `ASR_MODEL`（三者齐全） | 由 `ASR_STYLE` 决定 | 用户自定义 | 接入 Groq / OpenAI / 自建 |

> **要点**：硅基流动与 Qwen 是内置预设，`base_url`/`model` 已写死默认值，**只需填 Key**；
> 仅当要覆盖默认（`SILICONFLOW_BASE_URL`/`SILICONFLOW_ASR_MODEL` 等）或接入自定义端点时才需额外配置。
> 默认尝试顺序为「硅基流动 → DashScope」，可用 `ASR_PROVIDER=a,b` 显式改序；文件超某 provider 上限会自动跳过并在错误里说明。

- ASR 结果无精确时间戳时，按中文标点切分并合并为 ≥20 字的分段，前端 `language_name` 展示「语音识别 · <provider>」，
  `fmtTs(undefined)` 对无时间戳分段自动留空——**前端零改动即可渲染**。

## 四、能力三：AI 总结 / 思维导图 / 问答（多服务商大模型）

`ai` 门面在同一套多服务商配置（`config.py`）与调用层（`llm.py`）之上，提供三种「字幕 → 大模型」能力，
彼此同构、可插拔；未配 Key 统一抛 `AINotConfiguredError`（→ HTTP 503），调用/解析失败各自抛语义化异常（→ 502）：

| 能力 | 门面函数 | 产物 | 落库缓存 |
|------|---------|------|---------|
| 总结 | `ai.summarize(text, title)` | 结构化总结（摘要/要点/章节/关键词） | 是·跨 URL 复用 |
| 思维导图 | `ai.build_mindmap(text, title)` | 层级树（中心主题 + 多级分支） | 是·跨 URL 复用 |
| 问答 | `ai.ask(text, title, question, history=)` | 基于字幕的多轮回答 | 否·交互式（会话级） |

### 多服务商配置（config.py）
一份代码接入多家 OpenAI 兼容端点，靠环境变量切换，新增服务商只在 `PROVIDERS` 加一行：

| provider | 默认端点 | 默认模型 | Key 变量（支持多别名） |
|----------|---------|---------|----------------------|
| deepseek | `api.deepseek.com/v1` | `deepseek-chat` | `DEEPSEEK_API_KEY` |
| zhipu（智谱 GLM） | `open.bigmodel.cn/api/paas/v4` | `glm-4-flash` | `ZHIPU_/GLM_/BIGMODEL_API_KEY` |
| qwen（通义） | `dashscope.../compatible-mode/v1` | `qwen-plus` | `DASHSCOPE_/QWEN_API_KEY` |
| kimi（Moonshot） | `api.moonshot.cn/v1` | `moonshot-v1-8k` | `MOONSHOT_/KIMI_API_KEY` |
| openai | `api.openai.com/v1` | `gpt-4o-mini` | `OPENAI_API_KEY` |

**标识解析（`_resolve_provider`）**：精确 provider > 别名（`glm→zhipu`、`tongyi→qwen`、`moonshot→kimi`、`gpt→openai`）> 前缀
（用户常把「服务商-模型」连写，如 `kimi-k2.6`、`gpt-4o`，前缀命中时把完整值作为 model 覆盖）。
**命名兼容**：推荐 `AI_*`（`AI_PROVIDER`/`AI_API_KEY`/`AI_MODEL`/`AI_BASE_URL`），同时兼容旧的 `LLM_*`（含 `LLM_MODEL_ID`）。

### LLM 调用（llm.py）
httpx 统一调 `/chat/completions`，不绑厂商 SDK。针对**推理类模型**（Kimi-k2、OpenAI o 系列只接受默认 temperature，
传自定义值报 400 `only 1 is allowed`）做了**采样参数降级重试**：命中此类 400 时移除 `temperature`/`max_tokens`，
用服务商默认值重试一次。

### 总结：输出结构（summary.py）
强约束 LLM 输出 JSON，并做稳健解析（容错 ```json 围栏与前后杂文本）与字段规整，前端拿到稳定结构：

```json
{
  "one_line": "一句话概括（≤40字）",
  "summary": "详细摘要（150~300字）",
  "key_points": ["要点1", "要点2"],
  "chapters": [{"title": "章节名", "summary": "该部分讲了什么"}],
  "keywords": ["关键词1"],
  "model": "服务商 · 模型",
  "truncated": false
}
```

- 单次喂给 LLM 的文本上限 `_MAX_CHARS = 30000`，超长自动截断并置 `truncated=true`（前端提示「基于前半部分」）。
- 语义化异常：`AINotConfiguredError`（未配 Key → HTTP 503 引导配置）、`SummarizeError`（调用/解析失败 → HTTP 502）。

### 思维导图：提示词 + 树规整 + 缓存（mindmap.py）
门面 `ai.build_mindmap(text, title)` 与总结**同构**：缓存键（文本+模型+`PROMPT_VERSION`）→ 命中返 `cached=true`
→ 未命中经 `mindmap_flight`（single-flight）调 LLM → 规整落库、跨 URL 复用。要点：
- 提示词强约束 LLM 输出 `{title, children:[{title, children:[]}]}` 的 JSON；`_extract_json` 容错 ```json 围栏与前后杂文本。
- `_find_root` 兼容树被包在 `root/mindmap/tree/data` 里或直接返回数组；`_normalize_node` 递归统一为 `{title, children}`，
  并**限深 `_MAX_DEPTH=4`、限宽 `_MAX_CHILDREN=8`**、裁剪空节点，兼容 `name/text/label`、`nodes/sub/items/child` 等别名字段。
- 解析失败抛 `MindmapError`（→ 502）；产物落 `mindmaps` 表，不设 TTL（键含模型+版本，变更即自然失效）。

### 问答：基于字幕的多轮 grounded 问答（qa.py）
门面 `ai.ask(text, title, question, history=)` 是**有状态多轮对话**：后端拼装 `[系统提示(含字幕) + 历史 + 当前问题]`
交给 LLM，强约束**只依据字幕作答**、超出范围时明确说「视频中没有提到相关内容」，规避幻觉。要点：
- `_sanitize_history` 清洗前端传入历史：只留 `user/assistant` 的非空消息，单条截断 `_MAX_HISTORY_ITEM_CHARS=2000`，
  仅保留最近 `_MAX_HISTORY_MESSAGES=8` 条，防止上下文无限膨胀。
- **不落库缓存**：问答交互式、每轮上下文不同、复用率低；会话状态由前端在内存保留（切 Tab / 刷新前不丢）。
  字幕本身已在转写层缓存，故每轮问答只需一次 LLM 调用，成本可控。
- 字幕/问题为空、调用失败或返回空 → `QAError`（→ 502）；未配 Key → `AINotConfiguredError`（→ 503）。

## 五、能力底座：内容缓存与存储层（阶段0）

转写（yt-dlp 抓取 / 音频下载 / ffmpeg / ASR）与总结（LLM 生成）都是**耗时且花钱**的重活。
原实现全链路零缓存，同一视频每次点击都从零重跑（实测转写 78s、总结 95s）。本层把这两类结果
**持久化缓存并全局共享**，让二次访问「秒开」（实测转写 0.03s、总结 0.01s）且不再重复消耗额度。

延续「门面 + 可插拔」风格，新增 `backend/storage/` 包；业务层（`transcribe` / `ai.summary`）只依赖门面，
不感知底层是 SQLite 还是（阶段1 的）Postgres：

| 模块 | 职责 |
|------|------|
| `db.py` | 按 `DATABASE_URL` 建 engine（默认 `data/mindpilot.db`，SQLite 开 WAL）、`Session`、幂等 `init_db()` |
| `models.py` | `transcripts` / `summaries` / `mindmaps` 三张表，用通用 `JSON` 类型（阶段1 可平滑换 Postgres JSONB） |
| `keys.py` | `normalize_url` + 缓存键：`transcript_key` / `summary_key` / `mindmap_key` |
| `repo.py` | 读写缓存（含 `get/put_mindmap`）、TTL 过期判定、`CACHE_ENABLED` 短路 |
| `singleflight.py` | 进程内按 key 串行化并发，相同请求只计算一次（转写 / 总结 / 思维导图各一通道） |

### 缓存键：命中率的关键
- **转写**：`sha256(normalize_url(url))`，按视频全局共享。`normalize_url` 会**丢弃跟踪/分享参数**
  （`utm_*`、`spm`、`vd_source`、`share_*` 等）、host 小写、去 fragment、query 排序——
  同一视频的不同分享链接归一到同一个键。
- **总结 / 思维导图**：`sha256(文本 + 模型 + PROMPT_VERSION)`（思维导图键加 `mindmap` 域前缀，与总结键空间隔离），
  **跨 URL 复用**（相同字幕即相同产物）；改提示词时手动 bump `PROMPT_VERSION` 即让旧缓存自然失效。
- **问答**：不缓存（交互式多轮、复用率低；字幕已在转写层缓存，每轮仅一次 LLM 调用）。

### 读写策略
- **TTL**：转写默认 30 天（`TRANSCRIPT_CACHE_DAYS`，`<=0` 永不过期）；总结 / 思维导图不设 TTL（键已含模型与版本）。
- **并发去重（single-flight）**：相同 key 的并发请求串行化，`fn` 内做「双重检查」，昂贵的抓取/ASR/LLM 只跑一次。
- **强制刷新**：`transcribe` / `summarize` 均支持 `refresh=True`，跳过缓存、重算并覆盖。
- **总开关**：`CACHE_ENABLED=false` 时读写直接短路（用于对照排障）。

### 服务层与前端接入（对上层透明）
- `transcribe(url)` / `summarize(text)` 统一为「**查缓存 → 未命中则计算 → 落库**」，`main.py` 无需感知；
  `/api/summarize` 因转写已缓存，重复总结 = 转写命中 + 总结命中 = 秒回。
- 前端 `app.js` 叠加**会话级 Map 缓存** + 客户端 `dedup` 去重（并发点击只发一次请求），
  命中时渲染「已缓存」徽标；未命中时用**分阶段文案 + 已用秒数计时**改善长等待体感。

> **阶段1 演进（已预留、当前不实现）**：改 `DATABASE_URL` 即迁 Postgres（`JSON`→`JSONB` + Alembic）；
> 进程内 single-flight 换 Redis 分布式锁以支持多实例；引入任务队列异步化 ASR/LLM；
> `transcripts` / `summaries` / `mindmaps` 可加 `user_id` / 配额维度（内容缓存仍全局共享）。

## 六、HTTP API

| 方法 & 路径 | 说明 | 主要错误码 |
|-------------|------|-----------|
| `GET /api/health` | 健康检查：`ffmpeg` / `ai`+`ai_provider` / `asr`+`asr_provider` / `db` 是否可用 | — |
| `GET /api/info?url=` | 解析视频信息（标题/封面/清晰度） | 400 参数、500 解析失败 |
| `POST /api/download` / `GET /api/download` | 服务端下载并流式回传（GET 便于浏览器原生下载、对手机/大文件友好） | 400 / 500 |
| `POST /api/transcribe` | 转写：缓存优先 → 字幕 → ASR 兜底；可选 `refresh` 强制重算，响应含 `cached` | 400 无字幕且无兜底 |
| `POST /api/summarize` | 一站式：转写（复用缓存）→ 大模型总结（带缓存）；可选 `refresh`，响应含 `cached` | 400 转写失败、503 未配 AI、502 总结失败 |
| `POST /api/mindmap` | 一站式：转写（复用缓存）→ 大模型思维导图（带缓存）；可选 `refresh`，响应含 `cached` | 400 转写失败、503 未配 AI、502 生成失败 |
| `POST /api/qa` | 一站式：转写（复用缓存）→ 基于字幕回答一个问题；入参 `question` + 可选 `history`（多轮上下文） | 400 转写失败、503 未配 AI、502 问答失败 |

前端为 `frontend/` 下单页应用，由 FastAPI `StaticFiles` 托管在根路径；支持单条 / 批量解析。
每张视频卡片下的 AI 面板为**四 Tab**：`总结摘要 / 字幕文本 / 思维导图 / AI 问答`——思维导图与问答**懒加载**
（点到才请求）、切 Tab 不重发（前端会话级 `Map` 缓存 + `dedup` 去重），问答为**多轮对话**（切走再切回保留上下文）。

## 七、配置（.env）

复制 `.env.example` 为 `.env` 填写（`.env` 已被 gitignore）。各段能力相互独立、均可选：

1. **AI 总结**：`AI_PROVIDER` + `AI_API_KEY`（或各家专属 Key）。不配则仅 `/api/summarize` 返回友好提示。
2. **字幕 Cookie**：`COOKIE_FILE` 或 `COOKIES_FROM_BROWSER`。用于 B站等需登录态才有语音字幕的平台。
3. **ASR 兜底**：`SILICONFLOW_API_KEY`（推荐·免费）或 `DASHSCOPE_API_KEY`；配多个则自动按序尝试。
4. **缓存 / 存储**：开箱即用，无需配置。可选 `DATABASE_URL`（默认项目内 SQLite，阶段1 改此行即迁 Postgres）、
   `CACHE_ENABLED`（默认 true）、`TRANSCRIPT_CACHE_DAYS`（转写 TTL，默认 30 天）。

> 安全红线：真实 Key 只放 `.env`，`.env.example` 永远保持占位符。

## 九、技术栈与依赖

- **后端**：Python 3.11、FastAPI、uvicorn；`yt-dlp`（解析下载）、`imageio-ffmpeg`（内置 ffmpeg）、
  `requests`（抖音专用）、`httpx`（LLM/ASR 调用）、`python-dotenv`（读 `.env`，可选）、
  `SQLAlchemy`（存储层 ORM，阶段0 内容缓存）。
- **前端**：原生 HTML/JS 单页 + Tailwind 风格样式，无构建步骤。
- **存储**：阶段0 用 SQLite 单文件（`data/mindpilot.db`，已 gitignore）持久化缓存转写/总结结果，
  经 SQLAlchemy ORM 抽象，阶段1 改 `DATABASE_URL` 即可迁 Postgres；下载临时文件仍用完即清。
